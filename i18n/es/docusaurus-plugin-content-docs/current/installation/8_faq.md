### ¿Cómo actualizo Gladys?

Te recomendamos usar [Watchtower](https://github.com/nicholas-fedor/watchtower), un contenedor Docker que se ejecuta en paralelo a Gladys. Comprueba periódicamente si hay nuevas versiones de Gladys y actualiza el contenedor automáticamente.

Consulta la [guía de instalación con Docker](/es/docs/installation/docker#auto-upgrade-gladys-with-watchtower) para ver el comando exacto que debes ejecutar.

### ¿Quién usa Gladys Assistant 4?

Gladys Assistant v4 se lanzó en [noviembre de 2020](/es/blog/lancement-gladys-assistant-4) y desde entonces se desarrolla activamente, con una nueva versión cada pocas semanas.

Gladys Assistant lo instalan usuarios de todo tipo:

- Principiantes absolutos, que quieren automatizar su casa con un producto sencillo y potente que además respete su privacidad.
- Desarrolladores a los que les encanta poder programar para mejorar su propia casa. ¡Muchos de ellos contribuyen a este proyecto de código abierto!
- Profesionales, que gestionan grandes flotas de sensores (Sí, estamos hablando de ti, [@Terdious](https://community.gladysassistant.com/u/terdious/summary) 😛)

### ¿Cómo puedo contribuir al proyecto?

Gladys Assistant es totalmente de código abierto y está disponible en [GitHub](https://github.com/GladysAssistant/gladys).

Cualquier PR es bienvenida 🙂

Si quieres contribuir, pásate por [la comunidad](https://community.gladysassistant.com/) para hablar de las funciones que quieres desarrollar. Así podrás coordinarte con los demás desarrolladores y asegurarte de que nadie esté trabajando ya en ello. ¡También será una buena ocasión para comentar las "especificaciones" antes de ponerte a desarrollar!

### ¿Cuál es la filosofía del proyecto?

El objetivo del proyecto es crear un software de domótica:

- **Respetuoso con la privacidad**: los datos se almacenan localmente, en casa del usuario.
- **Fácil de usar**: la experiencia de usuario es nuestra prioridad. Gladys se ha desarrollado cuidando cada detalle; cada función se ha pensado a fondo antes de desarrollarse. No son las limitaciones técnicas las que definen nuestras decisiones de producto, sino que son nuestras exigencias de producto las que nos obligan a encontrar soluciones técnicas.
- **Diseño**: la bonita interfaz de Gladys Assistant es el sello distintivo del proyecto. Dedicamos mucho tiempo a que siga siendo así.
- **Eficiente**: Gladys debe poder soportar cierta carga sin que la interfaz pierda fluidez.
- **Ligero**: queremos que el software tenga un impacto mínimo en el sistema del usuario. Dedicamos mucho tiempo a analizar las dependencias que usamos para ofrecer un producto ligero.
- **Estable**: Gladys debe mantenerse estable a largo plazo. Queremos que nuestros usuarios usen Gladys durante muchos años, sin interrupciones, con actualizaciones continuas y sin fallos.
- **Seguro**: aplicamos todas las buenas prácticas para garantizar que Gladys sea seguro. Contamos con procesos automatizados que garantizan que ninguna nueva versión de Gladys introduzca regresiones de seguridad.

### Wie aktualisiere ich Gladys?

Wir empfehlen [Watchtower](https://github.com/nicholas-fedor/watchtower), einen Docker-Container, der parallel zu Gladys läuft. Er prüft regelmäßig, ob neue Gladys-Versionen verfügbar sind, und aktualisiert den Container automatisch.

Den genauen Befehl findest du in der [Anleitung zur Docker-Installation](/de/docs/installation/docker#auto-upgrade-gladys-with-watchtower).

### Wer nutzt Gladys Assistant 4?

Gladys Assistant v4 wurde im [November 2020](/de/blog/lancement-gladys-assistant-4) veröffentlicht und wird seitdem aktiv weiterentwickelt, mit einer neuen Version alle paar Wochen.

Gladys Assistant wird von ganz unterschiedlichen Nutzern installiert:

- Absolute Einsteiger, die ihr Zuhause mit einem einfachen, leistungsstarken Produkt automatisieren möchten, das zugleich ihre Privatsphäre respektiert.
- Entwickler, die es großartig finden, dass sie für ihr eigenes Zuhause programmieren können. Viele von ihnen tragen zu diesem Open-Source-Projekt bei!
- Profis, die große Flotten von Sensoren verwalten (Ja, wir reden von dir, [@Terdious](https://community.gladysassistant.com/u/terdious/summary) 😛)

### Wie kann ich zum Projekt beitragen?

Gladys Assistant ist vollständig Open Source und auf [GitHub](https://github.com/GladysAssistant/gladys) verfügbar.

Jeder PR ist willkommen 🙂

Wenn du beitragen möchtest, schau in [der Community](https://community.gladysassistant.com/) vorbei, um über die Funktionen zu sprechen, die du entwickeln möchtest. So kannst du dich mit den anderen Entwicklern abstimmen und sicherstellen, dass nicht schon jemand daran arbeitet. Das ist außerdem eine gute Gelegenheit, die „Spezifikationen“ zu besprechen, bevor es an die Entwicklung geht!

### Welche Philosophie verfolgt das Projekt?

Das Ziel des Projekts ist es, eine Hausautomations-Software zu entwickeln, die folgende Eigenschaften hat:

- **Datenschutzfreundlich**: Die Daten werden lokal beim Nutzer gespeichert.
- **Einfach zu bedienen**: Die Benutzererfahrung steht bei uns im Mittelpunkt. Gladys wurde mit viel Liebe zum Detail entwickelt; jede Funktion wurde durchdacht, bevor sie umgesetzt wurde. Nicht technische Einschränkungen bestimmen unsere Produktentscheidungen, sondern unsere Produktanforderungen zwingen uns, technische Lösungen zu finden.
- **Design**: Die schöne Oberfläche von Gladys Assistant ist das Markenzeichen des Projekts. Wir investieren viel Zeit, damit das auch so bleibt.
- **Leistungsfähig**: Gladys muss eine gewisse Last bewältigen können, ohne dass die Oberfläche an Flüssigkeit verliert.
- **Schlank**: Die Software soll das System des Nutzers so wenig wie möglich belasten. Wir verbringen viel Zeit damit, die verwendeten Abhängigkeiten zu analysieren, um ein schlankes Produkt zu liefern.
- **Stabil**: Gladys muss langfristig stabil bleiben. Unsere Nutzer sollen Gladys über Jahre hinweg verwenden können – ohne Ausfallzeiten, mit kontinuierlichen Updates und ohne Störungen.
- **Sicher**: Wir setzen alle bewährten Praktiken um, damit Gladys sicher ist. Automatisierte Prozesse stellen sicher, dass mit keiner neuen Version von Gladys Sicherheitsrückschritte eingeführt werden.
